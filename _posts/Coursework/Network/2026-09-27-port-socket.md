모험가가 `203.0.113.10` 마을 회관에 도착했다. 그런데 일반 안내, 원격 관리, 빵 주문 창구가 나란히 있다. 건물은 찾았지만 어느 창구에 요청할지 아직 정하지 못한 것이다.

네트워크에서도 같은 컴퓨터 안에 여러 서비스가 동작할 수 있다. 이때 **포트(Port)**가 어느 통신 끝점으로 전달할지 구분하는 번호로 쓰인다.

## IP 주소와 포트 번호

영상에서는 IP를 건물 주소, 포트를 창구 번호에 비유한다. 실제 IP가 인터페이스에 사용하는 주소라는 점은 이전 글에서 다뤘다.

```text
203.0.113.10:8000
└ IP 주소 ┘ └ 포트 ┘
```

같은 IP에서 443은 웹 서비스, 22는 SSH, 8000은 빵 주문 프로그램이 사용하도록 구성할 수 있다. 다만 번호를 정하는 것만으로 서비스가 열리지는 않는다. 프로그램이 해당 주소·포트에서 대기해야 하고, 경로와 방화벽 정책도 통신을 허용해야 한다.

전송 프로토콜도 중요하다. TCP와 UDP는 별도의 포트 공간을 사용하므로 `TCP 53`과 `UDP 53`은 같은 번호여도 구별된다. 프로토콜을 정한 문맥에서 IP와 포트로 끝점을 표현한다고 이해하면 된다.

## 소켓은 번호 자체가 아니다

포트가 창구 번호라면 **소켓(Socket)**은 프로그램이 통신을 위해 사용하는 접수대에 가깝다. 여기서는 인터넷 통신용 소켓을 다룬다. 프로그램은 운영체제의 소켓 인터페이스를 통해 데이터를 주고받는다.

TCP 서버에서는 새 연결을 기다리는 대기 소켓과, 연결을 받아 실제 데이터를 주고받는 소켓을 구분할 수 있다. 예를 들어 8000번에서 기다리는 접수 창구는 유지하면서 손님 A와 B를 위한 연결 소켓을 각각 사용할 수 있다. 둘의 서버 측 포트는 모두 8000일 수 있다. [Python 소켓 문서의 서버 예제 설명](https://docs.python.org/3/library/socket.html#example)

따라서 “포트 하나당 소켓 하나”, “한 포트에는 손님 한 명만 접속 가능”이라고 생각하면 안 된다.

## 손님에게도 번호표가 있다

클라이언트도 출발지 포트를 사용한다. 보통 운영체제가 임시 포트를 골라 주지만, 프로그램이 명시적으로 지정하는 경우도 있다.

영상의 클라이언트가 받은 번호표는 `51500`, 서버 창구는 `8000`이다. 요청과 응답의 방향을 나누면 더 명확하다.

| 방향 | 출발지 | 목적지 |
|---|---|---|
| 요청 | 198.51.100.23:51500 | 203.0.113.10:8000 |
| 응답 | 203.0.113.10:8000 | 198.51.100.23:51500 |

서버가 응답할 때는 클라이언트가 사용한 끝점으로 돌아온다. 클라이언트의 번호표와 서버의 창구 번호가 같을 필요는 없다.

## TCP 연결을 구분하는 네 값

일반적인 TCP 연결은 양 끝의 IP·포트 쌍으로 구분한다. 이를 네 값의 묶음인 **4-tuple**이라고 부른다. [RFC 9293의 TCP 연결 정의](https://www.rfc-editor.org/rfc/rfc9293.html#section-2.2)

| 항목 | 연결 A | 연결 B |
|---|---|---|
| 클라이언트 IP | 198.51.100.23 | 198.51.100.23 |
| 클라이언트 포트 | 51500 | 51501 |
| 서버 IP | 203.0.113.10 | 203.0.113.10 |
| 서버 포트 | 8000 | 8000 |

같은 네트워크 문맥과 시점에서 보면 두 연결은 출발지 포트가 달라 구별된다. 종료된 연결의 네 값은 이후 다시 사용될 수 있다. TCP와 UDP 트래픽까지 함께 구분하려면 전송 프로토콜을 더한 **5-tuple**을 사용한다.

주의할 점은 브라우저 탭과 연결이 일대일 대응하지 않는다는 것이다. 탭 두 개가 항상 포트 두 개를 새로 받는 것은 아니다. HTTP/2는 연결 하나에서 여러 스트림을 다룰 수 있다. 영상의 번호표 두 개는 **별도 TCP 연결 두 개를 연 경우**다. [HTTP/2 스트림과 다중화](https://www.rfc-editor.org/rfc/rfc9113.html#section-5)

## 포트 번호 구간과 자주 쓰는 값

포트 번호는 16비트로 표현한다. IANA는 다음처럼 번호 공간을 나눈다. 이 구분이 실제 OS의 임시 포트 선택 범위나 접근 허용 정책을 그대로 결정하는 것은 아니다. [IANA 포트 레지스트리](https://www.iana.org/assignments/service-names-port-numbers/service-names-port-numbers.xhtml)

| 구간 | 분류 |
|---|---|
| 0~1023 | System / Well-known |
| 1024~49151 | User / Registered |
| 49152~65535 | Dynamic / Private |

0은 첫 구간에 포함되지만 예약 번호다. 일부 소켓 API에서 포트 0으로 바인딩하면 OS가 사용 가능한 포트를 선택하게 하는 의미로 쓰인다. 일반적인 서비스 접속 포트로 0을 외우는 것은 아니다.

자주 만나는 기본 번호는 다음과 같다. 서비스 설정에 따라 바꿀 수 있으므로 번호만 보고 실행 중인 프로그램이나 보안을 단정하지 않는다.

| 포트 | 흔한 용도 |
|---|---|
| 22 | SSH |
| 53 | DNS — UDP와 TCP |
| 80 | HTTP |
| 443 | HTTPS |
| 3306 | MySQL |
| 5432 | PostgreSQL |
| 6379 | Redis |
| 8000 | Uvicorn 기본 포트 |

8000은 FastAPI 전용 포트가 아니다. FastAPI 앱을 Uvicorn으로 실행할 때 자주 보는 기본값이고 변경할 수 있다. [Uvicorn 설정 문서](https://www.uvicorn.org/settings/)

## 127.0.0.1:8000의 의미

`127.0.0.1`은 자신을 가리키는 IPv4 루프백 주소이고 `8000`은 접속할 포트 번호다. 둘을 합친다고 다른 사람도 내 서비스에 들어올 수 있는 공용 주소가 되는 것은 아니다.

친구가 자신의 컴퓨터에서 `127.0.0.1:8000`에 접속하면 친구 자신의 컴퓨터를 찾는다. “내 컴퓨터에서는 열리는데 친구는 못 들어온다”는 문제를 이해하려면 포트뿐 아니라 서비스가 어느 주소에서 대기하는지도 봐야 한다.

## 핵심 정리

- IP와 포트를 함께 보되 TCP·UDP도 구분한다.
- 소켓은 통신에 사용하는 끝점이며 포트 번호 자체와 같지 않다.
- 같은 서버 포트로 여러 TCP 연결을 받을 수 있다.
- 임시 출발지 포트, 서버의 서비스 포트, 루프백 주소의 역할을 구별한다.
